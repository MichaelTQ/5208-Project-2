# Stage 2：全量清洗、质量、站点与覆盖率

负责人 A。输入为 Stage 1 已核验的八个原始 CSV，共 48,538,713 条记录。使用 Python 3.11.14、Java 17、Spark 3.5.8，新加坡时区。

执行状态：2026-10-10 完成，独立验收 PASS。实际结果与证据见 `artifacts/stage2/STAGE_2_CHECK_REPORT.md`。

## 执行步骤

1. 检查 Stage 1 清单、输入大小和 SHA-256，保存 Stage 2 原始文件完整性结果；固定 config/stage2.json。全量计算继续 local[4]/4g；shuffle partitions 从 16 调整为 64，减少单分区压力，配置与耗时另行保存。
2. 用 Spark 逐年解析全部 12 个原始字段；保留字符串、source_year 和内容哈希。写出可恢复的 parsed Parquet；统计时间解析、单位/类型、降雨小数精度、非有限值、负值、坐标、日期和来源年份一致性、更新时间差。
3. 全量统计观测时间对 300 秒网格的偏移，再固定对齐规则。仅处理整五分钟和恰好提前一秒的时间；后者向前移动一秒，绝不向下取整。其它偏移隔离。对齐前后数量、最大调整量和碰撞分类留档。
4. 核查官方历史及实时数据说明。官方已说明五分钟更新、SGT、可能缺测和事后修订；当前未明确历史 timestamp 的区间起止或更新字段的首次可用性。将“读数对应 (规范时间-5分钟, 规范时间]”列为明确研究约定，interval_semantics 字段和 B 接口均保留假设状态，不伪称官方确认。
5. 标记无效观测：CSV 解析失败、空站点、无效时间、非 +08:00 时间格式、不支持的时间偏移、无效/非有限/负降雨、超过九位非零小数的精度、不正确单位/读数类型。全部写入 quarantine/invalid，记录原因，不填零。
6. 对有效候选记录按 station_id + 规范 observation_time 分组。统计输入条数、原始内容种数、降雨/位置一致性。雨量冲突或同一时刻位置冲突的组全部隔离；同值兼容组确定性选一条，优先原本整五分钟的记录，再按原始时间及内容哈希排序。保留 multiplicity、exact duplicate count 和质量标记；不相加、不平均。
7. 将正式观测写为按规范年份/月分区的 data/clean/observations。雨量使用 Decimal(20,9)，原始 reading_value 保留；类型为 mm/5min。大于等于 20 mm/5min 的值只标记复核，不因大值删除。未知更新语义、名称/坐标问题保留标记，不将后续更新时间当成预测时已知。
8. 生成原始与清洗后站点元信息组合、首次/末次出现、名称/设备/经纬度变化、位置差异复核表。组合的最早/最晚出现不等于连续有效运行期；不根据相同名称合并 ID。距离大于等于 100m 仅作疑似位置变化筛查。
9. 用全量规范时间序列统计时间间隔、内部缺口、至少一小时长缺口以及跨年边界。连续性跨来源年度计算。缺口只输出清单，不构造零降雨记录。
10. 生成 station-day、station-month、station-year 覆盖率。全年/全月/全日分母为对应 SGT 半开日历期间的五分钟网格（每天 288；闰年单独计算）。另给出首次至末次有效观测之间的 span coverage；未出现前/末次之后状态记为 unknown，不推断投运/停运日期。完整输出包括无有效观测的站点期间。
11. 保存质量汇总、清洗前后行数及精确降雨量去向、极端候选复核表、正式样例、版本化字段字典、规则与假设说明、B 交接说明和可并入报告的方法文字。
12. 用人工构造案例检验秒偏移、对齐碰撞、重复、冲突、负值/NaN、缺测、跨日/跨年和闰年。独立读取最终 Parquet，检查唯一键、时间网格、数值精度、记录/雨量守恒、覆盖率范围与合计、原始文件 SHA-256、字段与交接样例一致性。只有全部必需检查通过才生成 PASS 报告。

## 验收标准

- 原始文件不变；raw = invalid quarantine + conflict quarantine + clean unique + compatible redundant rows，统计严格闭合。
- 对可精确解析雨量，输入总量与保留/隔离/去重去向严格闭合；不通过浮点容差掩盖差异。
- 正式表 station_id + observation_time 唯一，规范时间整五分钟，任何调整仅 0 或 +1 秒。
- 无效雨量不进入正式表；极端候选完整保留，明确仍需核查。
- 原始时间、原值、原始内容哈希、来源年份、去重 multiplicity 和质量标记可追溯。
- 缺口数量与 coverage 缺失槽位一致；所有 coverage 在 [0,1]；闰年 2020/2024 分母为 105,408。
- 官方事实与研究约定区分清楚。数据清洗 PASS 不等于时间语义得到官方确认、极端值完成人工气象核验，或实时部署效果得到验证。
- B 获得明确路径、字段类型、有效记录条件、假设与可复查的边界示例。Stage 2 不构造 B 的特征/标签或训练模型。
