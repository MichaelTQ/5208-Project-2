# Stage 1：来源、环境、原始数据和样本接口

执行日期：2026-10-10（Asia/Singapore）。负责人：A。

## 目标与边界

为后续 Spark 清洗和 B/C 开发建立可复现基础。获取 2017–2024 原始数据，验证字段与样本读写，记录尚待查明的时间语义。原始文件保持原样。此阶段不产生正式清洗数据、模型特征、标签或气候分析结论。

## 执行步骤

1. 检查工作目录、项目指令和现有材料；建立 config、scripts、docs、data、artifacts、tests 目录。
2. 记录操作系统、架构、CPU、内存、磁盘余量和已有软件。使用项目内 Python 3.11.14、Eclipse Temurin Java 17、PySpark 3.5.8；锁定依赖。Spark 首版使用 local[4]、4 GB driver memory、16 个 shuffle partitions、新加坡时区。
3. 下载 Java 官方归档，核对发布方 SHA-256 后解压到 .runtime；建立 .venv；安装固定依赖；保存实际版本。
4. 从官方 collection metadata 核对八个 dataset ID。逐年保存 dataset metadata 和数据页面参考。下载完整 CSV，使用 .part 文件避免把中断文件误认为完整文件；记录字节数和 SHA-256。
5. 逐年以流式 CSV 解析检查表头、统计实际数据行数。提取四个固定站点在首个观测日、末个观测日和首个有雨日的全部记录。首末日组成跨年边界样本；若边界缺测，保留真实缺口。
6. 制定初版字段字典：保留 12 个原始字段及原始观测时间字符串，增加解析后的 observation_time、rainfall_mm、经纬度和 source_year。此时不对齐时间、不去重、不填补缺测、不改变降雨精度。
7. 用 Spark 读取样本并解析时间；检查跨年份 schema、时区、空值、负值、单位、读数类型、站点、秒数和有雨/无雨覆盖。写入 Parquet 后重读，比较记录多重集合完全一致，单独验证 +08:00 时间在 Spark 中的 epoch 与 Python 一致。
8. 运行下载辅助逻辑的必要测试及独立验收检查；核对八个原始文件、metadata、清单、样本和 Parquet；保存 JSON 证据及可阅读的检查报告。
9. 写 README、统一环境说明、B/C 接口说明及 AI 使用记录。

## 验收标准

- 八个年度元信息正确且表头一致；八个完整 CSV 与清单记录的大小、校验值、实际行数一致。
- Python 3.11.14、Spark 3.5.8、Java 17 启动成功；配置和依赖可查。
- 样本覆盖八年、至少四站点、零与正降雨、2017 非整五分钟时间戳，以及各年的首末观测日。
- 样本时间和数值解析成功；CSV 到 Parquet 再重读不丢行、不改值、不改变时间。
- 所有样本结果明确是样本检查；不将其表述为全量质量检查结果。
- 不确定的区间起止含义、更新字段语义与站点运行期在后续报告注明假设。用户后来已明确 Lecture 5/6 不需要提供，不列为后续事项。
